phone backup & cleanup · android, from the mac

Setup - 1. Map - 2. Copy - 3. Delete - 4. Clean in apps - 5. Afterwards - By hand

The rule: copy, check, then delete, never move. phone-dump.sh does all three over USB, and deletes only files whose checksum matches on the drive. Anything new or changed stays on the phone.

Setup (once)

adb on the Mac

brew install android-platform-tools

USB debugging on the phone

  • Settings → About phone → tap OS version (MIUI/HyperOS) or Build number 7 times.
  • Settings → Additional settings → Developer options → USB debugging on.
  • Plug in, accept the "Allow USB debugging" prompt.
adb devices

The phone should be listed as device, not unauthorized.

Get the script

mkdir -p ~/bin && cd ~/bin
curl -fsSO https://home.tailaccc17.ts.net/docs/phone-dump.sh
chmod +x phone-dump.sh

Fetch it again to get updates. The commands below assume you run them from ~/bin.

1. Map what takes space

./phone-dump.sh map

It prints a tree of internal storage and of the SD card, biggest first, then the 15 apps using the most space. A top-level folder shows from 100 MB; a subfolder shows when it is 100 MB or more and at least a quarter of its parent, so the tree follows where the space really goes (down to WhatsApp/Media/WhatsApp Video) without listing every album.

  • Folders (DCIM, WhatsApp media, Screenshots, ScreenRecorder, Movies, Recordings) can be copied off: step 2.
  • App data lives inside the app and can't be copied out usefully: clean it in the app, step 4. An app's data includes its folder under Android/media, so WhatsApp counts once, not twice.
  • Pictures/.thumbnails is the gallery's thumbnail cache: safe to delete, it rebuilds smaller once the photos are gone.
  • "System" in Settings → Storage can't be freed. Folders under 100 MB aren't worth the effort.

2. Copy and check

Plug in the drive, set the dump folder once for the session, then copy each big folder. Nothing is deleted at this step.

DUMP=/Volumes/<drive>/phone-dump/$(date +%F)
./phone-dump.sh copy internal DCIM/Camera "$DUMP"
./phone-dump.sh copy internal Android/media/com.whatsapp/WhatsApp "$DUMP"
./phone-dump.sh copy sd DCIM "$DUMP"

Folders are relative to the volume: internal is the phone's own storage, sd the card (found by itself). The drive mirrors the phone: $DUMP/internal/DCIM/Camera, $DUMP/sd/DCIM…

Done when it says N of N phone files are identical on the drive. If some are missing or different, or the copy was interrupted (lid closed, cable out), run the same copy again: it fetches only what's missing or different. verify (same arguments) re-checks without copying. Keep the same $DUMP date when you come back to it.

caffeinate -i ./phone-dump.sh copy internal DCIM/Camera "$DUMP"

caffeinate -i keeps the Mac from going to sleep while a long copy runs. Closing the lid still puts it to sleep.

3. Delete what was checked

./phone-dump.sh delete internal DCIM/Camera "$DUMP"
./phone-dump.sh delete internal Android/media/com.whatsapp/WhatsApp/Media "$DUMP"
./phone-dump.sh delete sd DCIM "$DUMP"

It hashes both sides again, shows how many files match, asks, deletes only those, and prints the folder size before and after. Photos taken since the copy are kept.

Keep the recent ones on the phone

./phone-dump.sh delete sd DCIM "$DUMP" --keep-days 365

Deletes only verified files older than 365 days, and says how many files and GB it would delete and keep before asking. Age is the file's modification date, which for camera photos is when they were taken. A file whose date changed when it was moved counts as newer and is kept.

WhatsApp: delete …/WhatsApp/Media only, never the whole WhatsApp folder: Databases and Backups hold the chat history.

Google Photos: if backup is on, never delete from inside the Google Photos app: that deletes the cloud copy too. Deleting with this script leaves the cloud alone.

adb reboot

After a delete, so the gallery stops showing the deleted photos.

4. Clean inside apps

  • Any app: Settings → Apps → sort by size → the app → Storage → Clear cache. Never Clear data: that resets the app.
  • WhatsApp: Settings → Storage and data → Manage storage. Largest files and "forwarded many times" first.
  • Telegram: Settings → Data and Storage → Storage Usage → Clear cache. Set "Keep media" to a week.
  • Podcasts: delete played episodes, or point the download folder at the SD card.
  • Browser: clear cached data, not cookies.
  • Speech/TTS: remove voice packs for languages you don't use.
  • Gallery: empty Recently deleted, which keeps photos for 30 days.

5. Afterwards

  • Camera → settings → storage location → SD card. The camera falls back to internal storage when the card is full or was unmounted. Check again a week later.
  • The drive is now the only copy. Make a second one (another drive, later the NAS) before calling it done.
  • Dump again before the SD card is nearly full, not after.

By hand (what the script does)

Where things are

WhatPath on the phone
Internal storage/storage/emulated/0 (also /sdcard, a link: add a trailing / with du)
SD card/storage/XXXX-XXXX, shown by adb shell ls /storage
CameraDCIM/Camera
Screenshots, screen recordingsDCIM/Screenshots, DCIM/ScreenRecorder (MIUI); Pictures/Screenshots elsewhere
WhatsApp mediaAndroid/media/com.whatsapp/WhatsApp/Media
TelegramAndroid/media/org.telegram.messenger

Sizes

adb shell du -d2 -m /storage/emulated/0 | sort -n
adb shell dumpsys diskstats

Copy, keeping dates

adb pull -a /storage/emulated/0/DCIM/Camera /Volumes/<drive>/dump/

Compare checksums (macOS)

adb shell 'cd /storage/emulated/0/DCIM/Camera && md5sum *' | sed 's/  / /' | sort -k2 > /tmp/phone.md5
(cd /Volumes/<drive>/dump/Camera && md5 -r *) | sort -k2 > /tmp/drive.md5
diff /tmp/phone.md5 /tmp/drive.md5 && echo identical

Copy with adb rather than Finder or Android File Transfer, which stall on big folders. A drive plugged straight into the phone works too (exFAT), but there's nothing to check the copy with.
